# Architektur

Systemüberblick, Datenmodelle und Diagramme. Kein Ersatz für die Specs — hier steht das Bleibende,
dort das Vorhaben.

**Sinnvolle Inhalte**

- `system-context.md` — was das System ist, wer es nutzt, womit es spricht.
- `containers.md` — die laufenden Teile und wie sie zusammenhängen.
- `data-model.md` — die zentralen Entitäten und ihre Beziehungen.
- `integrations.md` — Fremdsysteme, Protokolle, Verantwortlichkeiten.

**Diagramme** als Mermaid direkt im Markdown, damit sie versionierbar und ohne Werkzeug lesbar
bleiben. Ein Bild ohne Quelle wird nicht aufgenommen.

**Regel:** Was hier steht, muss stimmen. Ein veraltetes Architekturdokument ist schlimmer als
keines, weil ein Agent es glaubt. Wer eine Struktur ändert, zieht das Dokument nach — oder löscht
den überholten Teil.
